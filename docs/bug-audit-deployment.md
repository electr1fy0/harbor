# Deployment, service, builder, runtime, and sandbox bug audit

This ledger records 27 distinct, reproducible defects corrected in this audit. Related input cases and code paths that share one underlying failure are grouped together; the count does not include hardening without a demonstrated faulty behavior.

1. **Failed service links could leave empty applications behind.** `internal/service/manager.go`: `Link` created the app before looking up and validating the requested service and accepted invalid app names until the store operation. A missing, non-bindable, or rejected service/name could therefore leave an app visible without a binding. Service identity, type, state, and app-name validation now precede creation; `BindingManager.Link` retains the same checks for direct callers. Regression tests: `TestLinkUnknownServiceDoesNotCreateApplication`, `TestLinkInvalidApplicationNameDoesNotCreateApplication`, `TestLinkRejectsDuplicateDatabaseURLAndNonReadyService`, and `TestLinkRejectsLegacyPostgresAndCancellation`.

2. **Rejected settings could create an application.** `internal/deployment/settings.go`: configuring an unknown app first created it, then rejected reserved/invalid environment keys or invalid memory, CPU, or task limits. Input-independent validation now runs before app creation, while binding-specific checks remain after loading bindings. Regression test: `TestRejectedConfigureDoesNotCreateApplication`.

3. **Scheduled backup decisions were based on a truncated service-wide page.** `internal/service/data_services.go`: scheduler and retention queried the UI-oriented latest-100 service backup page, so many recent manual backups (or another binding's snapshots) could hide this binding's scheduled history, causing overscheduling and preventing old scheduled snapshots from being pruned. They now query the binding's complete scheduled history. Regression test: `TestScheduledBackupDecisionsIgnoreServiceWideBackupPageLimit`.

4. **Starting scheduled backups with an already-canceled context permanently disabled the loop.** `internal/service/data_services.go`: `StartBackups` latched its one-time started flag before observing cancellation. It now checks cancellation before and under the lifecycle mutex. Regression test: `TestStartBackupsDoesNotLatchAnAlreadyCanceledContext`.

5. **Legacy deployments with no log path could prevent application deletion.** `internal/deployment/operations.go`: deletion passed an empty log path to managed-path validation, which resolves it as the current working directory and rejected deletion. Empty legacy paths now mean there is no log file to remove. Regression coverage: `TestDeleteHonorsPreserveDataForBoundSQLiteDatabase` includes a stopped legacy deployment with an empty `LogPath` and verifies deletion succeeds.

6. **An already-canceled app operation could still acquire an available lock and mutate state.** `internal/deployment/service.go`: Go's `select` could choose the ready lock token even when the context was already canceled. `lockApp` now checks cancellation before registration and rechecks after acquiring the token, releasing its reference safely. Regression test: `TestCanceledContextCannotMutateThroughAnAvailableAppLock`.

7. **Health probes finishing during daemon shutdown could be recorded as failures.** `internal/deployment/operations.go`: the service context canceled a probe, but its error path could still update deployment health and trigger failure behavior. The probe now discards results after shutdown, including after waiting for the state mutex. Regression test: `TestShutdownCancellationDoesNotCountAsHealthFailure`.

8. **Failed release persistence could leave unpublished build artifacts behind.** `internal/deployment/service.go`: after a successful build, a failed `SaveRelease` (or cancellation before persistence) returned without removing the artifact directory. Cleanup now checks whether the exact release artifact became durable before safely removing it. Regression test: `TestFailedReleasePersistenceCleansUnpublishedArtifact` covers a persistence collision and cancellation after build output is materialized.

9. **Long managed file copies ignored cancellation.** `internal/builder/builder.go` and `internal/service/data_services.go`: source staging, fallback output copying, release publication, backup restore, and export member copies used non-context-aware file copies, so canceled operations continued consuming I/O and could leave partial files. Copying now checks the operation context throughout and removes incomplete destinations. Regression tests: `TestCopyRegularFileStopsWhenContextIsCanceledMidCopy`, `TestCopyWithContextStopsWhenCanceledDuringWrite`, and `TestCopyRegularFileRemovesDestinationWhenContextIsCanceled`.

10. **Source hashes did not distinguish trees that differed only by empty directories.** `internal/builder/builder.go`: hashes were emitted for files only, so adding/removing an empty source directory left the release source hash unchanged. Directory entries and file/directory type markers are now hashed. Regression test: `TestCopySourceHashIncludesEmptyDirectories`.

11. **Capacity preflight could overflow candidate/build overlap arithmetic.** `internal/deployment/operations.go`: adding two valid large byte counts could wrap negative and report that an impossible overlap fit in available memory. The sum now saturates and reports `CanFit=false` on overflow. Regression test: `TestPreflightOverlapSaturatesOnOverflow`.

12. **Repeated IDs in a batched systemd inspection could return misaligned results.** `internal/sandbox/systemd.go`: duplicate IDs were sent as duplicate unit requests; systemd may return one property block, leaving later output positions as empty success results. IDs are now queried once and their result/error is copied to each original position. Regression test: `TestSystemdInspectManyDeduplicatesRepeatedIDsAndKeepsPositions`.

13. **A non-file containers policy path was treated as a valid existing policy.** `internal/runtime/oci.go`: `Stat` accepted directories and followed symlinks, causing policy setup to silently succeed without a usable regular policy file. Setup now uses `Lstat`, rejects symlinks/non-files, and surfaces inspection errors. Regression test: `TestEnsurePolicyJSONRejectsNonFilePolicy`.

14. **OCI cache hits could silently reuse a different image.** `internal/runtime/oci.go`: any existing rootfs directory was accepted without verifying its recorded image reference, allowing a deploy requesting a new image to run the stale cached image. Cache validation now requires safe metadata and an exact image-reference match. Regression test: `TestFetchAndUnpackRejectsStaleCacheAndIncompleteMountpoints`.

15. **OCI unpack could report success with unsafe or missing mountpoints, and ignored metadata publication failures.** `internal/runtime/oci.go`: mountpoint creation errors were discarded, symlink/non-directory mountpoints could be accepted, and runtime metadata marshal/write errors were ignored; old cache hits also skipped mountpoint validation. Fresh unpack and cache hits now validate/repair only missing real directories, reject unsafe entries, and publish metadata atomically with errors propagated. Regression tests: `TestFetchAndUnpackRejectsStaleCacheAndIncompleteMountpoints`, `TestFetchAndUnpackReturnsMetadataWriteFailure`.

16. **Host sandbox executable lookup ignored the child working directory for relative PATH entries.** `internal/sandbox/host.go`: bare commands were resolved before `cmd.Dir` was applied, so a `PATH=bin` entry looked under the daemon's current directory; empty PATH components were joined into `/command` rather than searching the child working directory. Lookup now resolves relative and empty components against the effective child working directory. Regression test: `TestHostStartResolvesRelativePathEntriesFromWorkingDirectory` exercises `PATH=bin`, `PATH=:bin`, and an explicitly empty PATH through `HostSandbox.Start`.

17. **Completed sandbox metadata accumulated without bound.** `internal/sandbox/host.go` and `internal/sandbox/systemd.go`: each unique completed host process remained in the map with its `exec.Cmd`, arguments, and environment, while stopped/failed systemd units remained in a separate map. Reaping releases host commands and both backends now retain only a bounded 64-entry FIFO of exit metadata for inspection. Regression tests: `TestHostBoundsCompletedProcessHistory` starts 65 real short-lived processes and verifies oldest eviction/latest inspection; `TestSystemdBoundsCompletedUnitInspectionHistory` verifies the same cache bound and recent snapshot behavior.

18. **A pre-canceled host stop still signaled the process.** `internal/sandbox/host.go`: `Stop` checked for completion but not context cancellation before sending SIGTERM/SIGKILL, so an already-canceled operation still changed process state. It now returns the cancellation before signaling. Regression test: `TestHostStopWithCanceledContextDoesNotSignalProcess` confirms the process remains running and then stops it with a live cleanup context.

19. **The configured build timeout excluded cache admission and source staging.** `internal/builder/builder.go`: the timeout context was created only after the cache lock and source copy completed, so a contended cache or slow source tree could exceed the configured maximum before cancellation began. The build deadline now covers cache waiting, source staging, and the existing command/output stages. Regression test: `TestBuildTimeoutCoversWaitingForBuildCache` holds the cache lock and confirms the build returns on its configured deadline before the lock is released.

Cross-area corroboration counted with frontend/onboarding item 7: deployment log reads
had the same tail-before-redaction failure. `LogsForDeployment` and `LogsBySource`
now read bounded byte lookbehind before redacting and trimming, and systemd journal
reads also request bounded earlier records when configured secrets contain newlines.
The stable raw cutoff prevents replacement shrinkage from exposing bytes that were
outside the original tail. Regressions `TestConfiguredSecretCrossingLogTailBoundaryIsRedacted`,
`TestRedactionShrinkCannotExposeSecretFromBeforeLogTail`,
`TestSystemdRuntimeLogTailUsesRedactionLookbehind`, and
`TestSystemdRuntimeLogRedactsSecretsAcrossJournalRecordLimit` cover deployment logs,
build-only and runtime-only source logs, shrinkage, and the journal's record limit.
These exercise the same root cause as `TestSafeLogTailRedactsSecretsBeforeTruncating`
in the frontend/onboarding ledger.

20. **A superseded automatic-restart timer could undo a manual start.** `internal/deployment/operations.go`: a timer checked its policy before waiting for the app lock, so a policy change or manual start could supersede it before admission; its error handler also retried whenever the app was still desired and restart remained enabled. A manual `Start` clears the timer deadline while leaving the policy enabled, so the stale timer could schedule another restart and mark the healthy app unhealthy. Admission and retry now require the original `NextRestartAt` token and enabled policy to still match under the service mutex. Regressions: `TestAutomaticRestartRechecksPolicyAfterWaitingForAppLock` and `TestAutomaticRestartRetryIgnoresScheduleClearedByManualStart`.

21. **Service names could be persisted that the UI could not address.** `internal/service/manager.go`: service creation accepted whitespace, uppercase, and otherwise invalid names, while the UI's shared name validator only accepted application-style slugs. Creation now applies the same slug contract before provider side effects; existing legacy service records remain readable. Regression test: `TestAddServiceRejectsNamesOutsideApplicationSlugContractBeforeProvisioning`.

22. **Node releases silently lost the root `bin` directory.** `internal/builder/builder.go`: generic source staging excluded `bin` for Go build artifacts, but Node projects commonly keep `bin/www` or build scripts there. Node staging and fallback output now retain it while Go keeps its exclusions. Regression test: `TestNodeBuildKeepsRootBinDirectoryInFallbackArtifact` builds a local fixture and checks the published artifact.

23. **Node dependency symlinks made otherwise valid artifacts unpublishable.** `internal/builder/builder.go`: npm and pnpm install layouts use internal links such as `node_modules/.bin/tool`, but artifact copying rejected every symlink. Node output now preserves safe relative links whose resolved targets remain inside the artifact and rejects external, dangling, or cyclic targets; source checkout links remain rejected. Regressions: `TestNodeBuildPublishesInternalPackageManagerSymlinks`, `TestNodeBuildRejectsExternalAndCyclicDependencySymlinks`, and `TestValidateArtifactSymlinksRejectsExternalAndCyclicTargets`.

24. **An in-flight health probe could apply an obsolete policy.** `internal/deployment/operations.go`: a probe captured its failure threshold before network I/O, then could withdraw production using that threshold after an administrator disabled the probe or raised the threshold. Results now revalidate the current policy snapshot while serialized with app state changes. Regression test: `TestOngoingHealthProbeDiscardsResultsFromSupersededPolicy` covers disabling and threshold changes while a response is held.

25. **Startup readiness timing reported only the first failed retry.** `internal/deployment/operations.go` and `internal/store/operations.go`: when a runtime failed readiness and the next startup attempt succeeded, stage duration used the first sandbox start and first health result, omitting later attempts. Each attempt now has a start boundary, and timing aggregation sums completed attempt intervals while excluding later ongoing health checks/runtime failures. Regressions: `TestStageDurationsAggregateStartupRetryAttempts` and `TestStartupRetryStageTimingsIncludeEveryAttempt`.

26. **A failed or missing scheduled snapshot suppressed its replacement.** `internal/service/data_services.go`: scheduling used the newest scheduled record's timestamp even when verification had failed or its snapshot file had disappeared, postponing a usable replacement for the whole interval. It now uses the newest available snapshot without a known verification failure, using cheap metadata checks; periodic scheduling does not perform a full integrity scan. Regression test: `TestScheduledBackupsDoNotTreatFailedOrMissingSnapshotsAsRecent`.

27. **Concurrent first backups could fail while initializing the shared directory.** `internal/service/data_services.go`: two requests could both observe a missing backup directory, then one returned `EEXIST` after the other created it. Creation now accepts that race and validates the resulting directory entry for symlinks, type, and permissions. Regression test: `TestConcurrentFirstBackupsShareDirectoryInitialization` starts 64 callers together.

Startup-cancellation extension cross-referenced with control round-two item 4: `NewWithContext` now checks daemon startup cancellation between persisted deployments and bounds stale systemd-unit cleanup by the startup context. `cmd/paasd` passes its signal context and returns through deferred listener/store cleanup. `TestNewWithContextHonorsCancellationBeforeSystemdReconciliation` and `TestNewWithContextCancelsSystemdReconciliationInFlight` cover early cancellation and cancellation while a fake `systemctl stop` is blocked; the latter verifies the persisted deployment is not reconciled after shutdown begins.
