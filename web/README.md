# Harbor dashboard

A local deployment control plane built with TanStack Start, Router, Query,
Form, and Table. UI primitives come from the Base UI shadcn preset `b6F9PjJnG`
(Nova, Figtree, neutral surfaces, yellow accent, Tabler icons).

## Run

Requires Bun 1.4+. Start Harbor's Go daemon from the repository root (see the
root README), then:

```sh
bun install
PAASD_SOCKET=/tmp/paasd.sock bun run dev
```

Open http://127.0.0.1:3000. The dashboard reads real application, release, log,
and service data through TanStack server functions over the daemon's Unix
socket. Offline and empty states are displayed when no daemon or projects are
available.

## GitHub import

Browse an owner's public repositories or paste `https://github.com/owner/repo`.
Set an app name, optional branch/tag/commit ref, and optional repository root.
The root must contain a valid `paas.yaml`; supported build/start contracts are
documented in the root README. The daemon checks out the repository and uses
the same pipeline as local CLI deploys.

To browse and deploy private repositories, provide `GITHUB_TOKEN` to **both**
the web process and Go daemon. Tokens stay server-side. With a token, repository
browsing includes repositories accessible to its user (filtered by owner).
This release supports manual deployment, not GitHub OAuth or automatic pushes.

## Configuration

Copy `.env.example` to `.env.local` for local Vite development, or export these
variables when starting production:

| Variable | Purpose |
| --- | --- |
| `PAASD_SOCKET` | Control socket; defaults to `/run/paas/paasd.sock` |
| `GITHUB_TOKEN` | Optional server-side GitHub API credential; also set on daemon for private clones |
| `PAASD_PUBLIC_ORIGIN` | Exact public dashboard origin, e.g. `https://dashboard.example.com` |
| `PAASD_ADMIN_PASSWORD_HASH` | Scrypt hash generated by `bun run hash-password`; never a plaintext password |
| `PAASD_SESSION_SECRET` | 32 random bytes encoded as 64 lowercase hexadecimal characters |

With all three public-auth variables unset, the app accepts loopback requests
only and does not require a login. Public mode requires all three valid values;
incomplete or malformed configuration fails closed. The dashboard validates
its exact configured public origin and Host and ignores forwarded-host headers.
It uses a signed, HTTP-only, secure session cookie, bounded login attempts, and
same-origin checks for state-changing requests. Do not prefix secrets with
`VITE_`.

Generate the password hash interactively with `bun run hash-password`. The
utility reads from a hidden TTY prompt; only the scrypt hash is printed. Store
the hash and a random session secret in the service environment file. See
[`../deploy/README.md`](../deploy/README.md) for the Caddy and systemd public
installation. The web process stays on loopback and should be able to open the
daemon control socket; public use requires the dedicated `paas-admins` socket
group in the deployment guide.

## Verify and build

```sh
bun run generate-routes
bun run typecheck
bun run lint
bun run test
bun run build
bun run smoke:public
PAASD_SOCKET=/tmp/paasd.sock bun run start
```

The Nitro build is written to `.output/`; `bun run start` binds it to
`127.0.0.1:3000`. `PORT` can select another port. Development uses Vite at the
same loopback address. For a public deployment, configure all three auth
variables and put Caddy in front of the loopback web and daemon services. The
Caddy TLS authorization check allows only domains explicitly configured on an
app; see [`../deploy/README.md`](../deploy/README.md). `bun run smoke:public`
exercises the production server bundle's login, logout, origin checks, and RPC
access boundary after `bun run build`.
